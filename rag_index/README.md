# RAG Index

This folder stores the saved FAISS retrieval bundle used by the RAG pipeline in [`rag/`](/Users/archana/Documents/ai-assisted-investing/rag/README.md).

The files here are generated artifacts, not hand-edited source files.

## Files In This Folder

- `documents.faiss`: the FAISS vector index used for semantic retrieval.
- `documents.json`: the full saved document payloads, including the exact text chunks that were embedded.
- `metadata.json`: lightweight metadata for each document, mainly for traceability and inspection.
- `index_info.json`: summary information about the bundle such as model name, document count, and embedding dimension.

## What Each File Is For

### `documents.faiss`

This is the binary FAISS index loaded by [`faiss_retriever.py`](/Users/archana/Documents/ai-assisted-investing/rag/faiss_retriever.py). It stores one vector per document.

### `documents.json`

This file contains the retrieval text plus metadata for every indexed document. It is the human-readable companion to the FAISS file and is what search results are mapped back to after vector lookup.

Each entry includes:

- `document_id`
- `text`
- `metadata`

### `metadata.json`

This is a lighter-weight view of the indexed corpus and is useful when you want to inspect:

- which tickers are present
- which document types were indexed
- dates and source URLs
- original source file paths under `data/`

### `index_info.json`

This records the bundle configuration needed to understand the saved index.

The current snapshot in this repository shows:

- model: `sentence-transformers/all-MiniLM-L6-v2`
- document count: `75`
- embedding dimension: `384`
- FAISS metric: `inner_product_on_normalized_embeddings`

If you rebuild the index later, these values may change.

## How This Folder Is Produced

The contents are generated by:

```bash
python3 rag/build_faiss_index.py
```

That script reads the JSON corpus under `data/`, creates embeddings, builds the FAISS index, and rewrites all files in this folder.

## How This Folder Is Used

At runtime, [`FAISSRetriever`](/Users/archana/Documents/ai-assisted-investing/rag/faiss_retriever.py) loads the bundle and checks that:

- the expected files exist
- the number of FAISS vectors matches the number of saved documents

Then `rag_insights.py` uses that retriever to find ticker-specific evidence for each ranked stock before generating an explanation.

## When To Regenerate

Rebuild `rag_index/` when:

- you add or update JSON files under `data/`
- you change the embedding model
- you want retrieval results to reflect newer source documents

## Practical Notes

- Treat this folder as generated state.
- Avoid editing the JSON files manually unless you are debugging the pipeline.
- If retrieval starts failing or looks stale, rebuilding this folder is usually the first thing to try.
